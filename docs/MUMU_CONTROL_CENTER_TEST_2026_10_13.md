# MuMu 控制中心与模式选择实测

设备：用户启动的 MuMu 实例 2，Android 12（API 32），1920 × 1080，ADB 127.0.0.1:16448。

## 功能验证

- 修复鼠标打开模式框后方向键焦点落到背景导航栏的问题：模式项显式允许焦点，打开时当前模式默认聚焦。
- 实际方向键测试：电视 → 主机 → 掌机 → 电视，每次确认后当前模式居中，另外两个模式在左右。
- 点击框外关闭、返回关闭、强制停止并重启恢复电视模式均通过。
- 选择框与所有模式按钮没有描边；面性图标与缓存模糊底板已截图检查。
- 25 项 JVM 单元测试通过。五项设置仪器测试全部通过，覆盖模块切换、遥控器返回、连续滚动同步、三个动画选项、时间与日期和秒数、应用模糊开关、插件模块。首次插件用例因上次遗留的同版本测试插件失败，清理后单独复测通过，其余四项首次通过。
- 正式 x86_64 APK 已安装并运行。测试期间 crash 缓冲区无异常记录。

## 正式包开合性能

不录屏时，连续六次控制中心开合：每次打开后停留 650ms，返回后停留 350ms，ADB 输入本身还有额外开销。

| 指标 | 结果 |
| --- | --- |
| 渲染帧数 | 286 |
| P50 | 6ms |
| P90 | 17ms |
| P95 | 19ms |
| P99 | 23ms |
| 新口径 Janky | 0 / 286 |
| 旧口径 Janky | 75 / 286（26.22%） |
| Missed Vsync | 0 |

旧口径仍存在掉帧，不能据此宣称稳定 60fps。模拟器 GPU 百分位返回 4950ms 等异常值，不用于评价。此数据只代表本次模拟器与静态壁纸，不代表低性能电视，也不能与不同分辨率的旧报告直接比较。

## 后续修订：固定位置与横向信号源

按最新要求取消选中后重新居中：主机、掌机、电视始终固定从左到右排列。MuMu 逐一点击三项，对比每项文字 bounds，三次切换全部保持不变，“当前模式”标记正确更新。

信号源共用 900 × 228dp 中央选择框与模糊底板，真实输入固定排序，超出三个时横向滚动，不因选择改变顺序。MuMu 没有 HDMI 等直通输入，已检查无输入提示、设置入口卡片、默认焦点和返回关闭；无法在该模拟器验证真实电视的 HDMI 切换。

最新构建与 25 项单元测试通过，正式包已更新到 MuMu。截图为 `test-shots/mumu-mode-fixed-order.png` 和 `test-shots/mumu-signal-source-horizontal.png`。
