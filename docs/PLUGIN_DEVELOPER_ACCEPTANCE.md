# API 1.1 独立开发者验收任务

状态：**等待未参与 SDK/宿主实现的开发者执行**。这份表格是测试脚本，不是已通过的报告。测试者可阅读公开 SDK 文档和示例，但不要阅读 Android 宿主 Kotlin 源码，也不要向实现者索取未公开接口。

测试宿主：[ABU Launcher 0.04 Beta 1](https://github.com/Mashiro000/ABU-launcher/releases/tag/v0.04-beta.1)。根据设备选择 arm64-v8a、armeabi-v7a、x86_64 或 universal APK；0.03 不支持本次 API 1.1 验收。起点为一个新的空插件项目，不复制现成示例作为最终成品。

## 任务 A：多页面设置插件

仅按 [`plugin-sdk/`](../plugin-sdk/README.md) 的入口完成：创建独立项目；首页展示至少三个数据项；点击进入详情页并通过 `navigation.params` 传 ID；提供设置页的输入框和开关；用 `storage` 在重新打开应用或重建插件进程后保留设置。界面必须能用触屏和遥控器方向/确认/返回操作。拒绝存储授权时要显示能理解的提示，不能空白或崩溃。

通过证据：源码仓库/提交、`.abu-plugin` 校验输出、安装/启用操作录像或截图、触屏/遥控器路径、拒绝权限和重新启动后的实际结果。

## 任务 B：两个插件协作

创建**两个独立插件包**。提供方声明版本化服务并处理至少两种方法；调用方通过 `services.resolve`/`services.call` 获取结果并绘制列表。停用提供方、版本不足、恢复提供方三种状态都有明确提示或降级。至少一个插件应有真实的设置或输入值，且不能用 JS 全局变量假装跨调用状态。

通过证据：两个源码仓库/提交与校验输出、安装和联动演示、停用/版本不符/恢复三种结果。可另选媒体数据源插件代替此任务，但须完成搜索、分页、离线/拒绝权限、HTTPS 域名限制和播放器交接。

## 发布与升级演练

在作者自己的源码仓库建固定标签 Release，上传包；使用自己的 Ed25519 密钥生成公钥、哈希、大小和签名元数据。按[官方库投稿指南](https://github.com/Mashiro000/ABU-plugins/blob/main/CONTRIBUTING.md)提交 `plugins/<ID>/plugin.json` 与 `versions/<版本>.json` 的 PR，让 CI 验证真实资产。随后发布一个更高版本，确认旧版本仍在目录中且按新到旧排列。测试用途的 PR 可标记为验收演练，是否合并由维护者决定；不要提交私钥或真实账号凭据。
