# ABU 复杂插件开发者文档与平台补齐计划

状态：实施中。本文件定义工作与验收标准；已完成与未完成项以 [`PLUGIN_DEVELOPER_PROGRESS.md`](PLUGIN_DEVELOPER_PROGRESS.md) 和实际代码、测试为准，不能仅凭计划内容认定功能已可用。

## 最终目标

一位不熟悉 ABU 内部 Kotlin 代码的第三方开发者，仅依靠公开的 SDK、文档和示例，可以独立完成有多个页面、设置、持久化数据、网络请求、遥控器交互和插件协作的复杂插件，完成本地调试、签名发布、官方库投稿与后续升级。

这里的“能开发”以实际操作验证：由未参与 SDK 实现的人按文档制作两个完整参考插件，途中不需要询问宿主源码作者，也不需要复制未公开的内部代码。

## 先承认目前的能力边界

| 开发者需要什么 | 0.03 当前实现 | 计划中的处理 |
| --- | --- | --- |
| 多页面与设置 | 插件可接管 `home`/`settings`/`player`，但 UI 协议只有少量节点，没有插件内导航、表单、列表或图片的完整契约 | 设计导航、状态和更丰富的原生 UI 节点；给每个节点规定遥控器、触控和返回行为 |
| 数据与异步工作 | 有隔离键值存储、HTTPS 请求；QuickJS 每次调用重新执行脚本，同步方法不能返回 Promise | 文档解释状态生命周期；提供宿主能力回调与持久化辅助 API；完善分页、超时、取消和错误语义 |
| 插件之间联动 | 有事件发布与服务注册/查找，但没有真正的服务方法调用 | 补充受控服务调用协议、调用方授权、版本约束、超时和卸载清理 |
| 系统设备能力 | USB/蓝牙名称存在，但调用会被明确拒绝 | 若要支持掌机类插件，实施受权限控制的能力桥和设备兼容测试；未完成前不得写成可用 |
| 媒体与数据源 | `data_source`/`subtitle` 只是类型名称，缺少完整宿主接入点 | 定义实际注册、查询、播放交接和错误协议，并做端到端示例；无法接入的类型标为暂不支持 |
| 扩展位置 | 当前可见完整页面和少数插槽；没有通用任意页面修改能力 | 发布稳定扩展点清单、布局边界和冲突规则；新增扩展点必须有可测宿主实现 |
| 包、版本与签名 | 文档和打包器对资源、包内签名、`hostApi` 存在不一致 | 收敛成一套经过代码验证的包规范与兼容规则 |

文档不能替代缺失的宿主接口。对上表中影响复杂插件开发的缺口，要么先实现并验证，再写“可用”；要么在文档中明确限制和替代方案。

## 阶段 1：定义稳定的开发者协议

1. 逐项核对安装器、QuickJS、Compose 渲染器、能力桥、媒体流程和官方库索引，列出“实际可用 / 仅有部分实现 / 尚未支持”。
2. 制定公开协议版本、最低宿主版本与向后兼容策略。`hostApi` 必须真正参与安装或启用校验；如果不采用该字段，要从工具、类型和示例中一致移除。
3. 确定 `manifest.json` 模式：ID、版本、类型、入口、页面、插槽、权限、网络域名、资源、依赖、兼容范围和更新规则。为每个字段给出合法与非法示例。
4. 统一 `.abu-plugin` 包格式。说明 Ed25519 签署完整包，签名和公钥保存在仓库索引中的现有做法；本地导入的信任级别单独说明。
5. 为每个公开 API 定义输入、输出、错误、大小限制、超时、权限、幂等性与 API 版本。明确 `slot:<名称>` 的输入格式，以及 QuickJS 不保留内存状态的事实。
6. 建立“宿主版本 × API/扩展点”兼容表和 SDK 更新日志。破坏性变更必须有迁移指南。

验收：协议说明、TypeScript 类型、宿主代码、示例和官方库格式使用同一套字段与版本定义；不存在文档承诺但实际总会失败的能力。

## 阶段 2：实现复杂插件必需的宿主能力

1. **UI 与导航**：支持插件内页面栈、参数传递、返回键、焦点恢复、滚动列表、图片、输入控件、加载/空状态/错误状态。每种节点都要有声明式模型、宿主渲染、焦点规则和边界测试。
2. **状态与后台工作**：提供按插件隔离的持久化接口、分页网络请求、明确的任务生命周期、取消/超时和权限撤回行为。避免让开发者依赖每次调用后会丢失的 JS 全局变量。
3. **插件协作**：在现有事件与服务发现之上实现真正的请求/响应服务调用；定义服务名、方法、版本、数据结构、调用方授权、不可用时降级和循环调用限制。
4. **媒体扩展**：为 `data_source`、`subtitle` 等已公开插件类型提供真正的注册和调用入口；媒体地址、账号凭据和播放请求只能经宿主能力桥传递，不能直接暴露宿主私有数据。
5. **设备能力**：若掌机模式需要 USB/蓝牙，按能力分别实现 Android 权限代理、设备发现/断连事件和用户授权 UI，并测试实际设备。未实现的能力保留为“计划中”，不放进可用 API 示例。
6. **安全与兼容**：插件无权覆盖授权、安全模式和账号页面；版本不匹配、异常或超时应返回清晰错误，并可恢复默认界面。

验收：有宿主端自动化测试和 Android 设备测试证明每项标记为“可用”的能力可实际调用；一个多页面插件能在遥控器和触控下连续完成真实任务。

## 阶段 3：交付可独立使用的 SDK 工具

1. 新增脚手架，例如 `npm run create:plugin -- --id com.example.demo --name Demo`：生成独立项目、清单、源码、类型、构建命令和 README；已有目录不覆盖。
2. 规范打包器：打入允许的资源，拒绝缺入口、路径越界、无效权限与超限文件；输出可复现的 `.abu-plugin`。
3. 新增包校验器：在安装前检查清单、JS 入口、协议版本、能力声明、ZIP 结构、大小、SHA-256 与签名。错误应指出文件、字段和修复办法。
4. 新增发布命令：用开发者自己的 Ed25519 密钥签名，生成大小、哈希、公钥、签名和官方库版本 JSON；私钥不得出现在输出包或 Git 中。
5. 提供本地调试命令或步骤，能看到插件 ID、调用阶段、能力拒绝、脚本异常和超时；日志默认隐藏 Token 等敏感值。

验收：在干净环境中从空目录运行“创建 → 编写 → 构建 → 打包 → 校验 → 安装 → 签名”，无需修改 SDK 内部路径或阅读 Kotlin 代码。Windows、macOS、Linux 的命令和依赖分别说明并验证。

## 阶段 4：写能支撑复杂项目的文档与参考实现

文档按开发者实际操作顺序组织，而不是只按内部模块排列：

1. **入门路径**：环境准备、安装 ABU、创建项目、第一次运行、修改按钮、重新安装与调试。
2. **开发手册**：目录结构、清单、生命周期、页面导航、UI 节点、焦点/返回、状态保存、网络、权限、事件、服务、媒体和设备能力。
3. **API 参考**：每个公开调用都有参数表、完整请求/响应 JSON、失败情况、权限、限制和最低宿主版本；说明同步 JS 方法如何发起宿主异步能力。
4. **设计模式**：多页面状态组织、列表分页、权限拒绝降级、插件依赖缺失、升级与数据迁移、慢网络、超时后恢复。
5. **故障排查**：安装失败、页面空白、脚本异常、焦点丢失、返回键、网络白名单、签名、公钥变更和插件协作问题的诊断步骤。
6. **兼容与变更**：公开版本兼容表、SDK 更新日志和从旧协议迁移的说明；明确 0.03 已支持与新宿主版本才支持的功能。

提供可单独构建的参考插件，不少于以下六个：

- Hello：最小 UI 与按钮事件。
- 多页面界面：完整页面、导航、设置、表单、列表、遥控器焦点与状态保存。
- 插槽扩展：在首页和播放器的现有扩展位置协作显示内容。
- 媒体/直播来源：数据拉取、分页、错误处理、宿主播放交接；以实际已接通的宿主 API 为准。
- 双插件联动：服务提供方与调用方、版本不符和提供方停用的降级。
- 设备模式：展示 USB/蓝牙授权、发现与断连；只有设备能力实现后才标记为可运行示例。

每个示例附完整源码、清单、构建与安装命令、预期界面、权限说明、测试步骤和对应的最低 ABU 版本。未完成宿主能力的示例不得伪装成可运行成品。

验收：开发者能够在不查宿主源码的情况下，把参考示例改造成自己的多页面、数据驱动插件，并解释其权限、状态与发布方式。

## 阶段 5：端到端验收与官方库发布

1. 自动测试 SDK：脚手架生成、构建、有效/无效包、资源、兼容范围、签名、复杂 UI 与服务交互。
2. 在 Android 真机或模拟器验证安装、启用、升级、降级、卸载、权限同意/拒绝、遥控器、触控、网络失败、进程重建和安全模式。
3. 做一次“陌生开发者演练”：只给公开文档，让测试者独立完成两个复杂任务——多页面插件与双插件协作（或媒体插件）。记录每次需要追问或阅读 Kotlin 的位置，并补齐后重测。
4. 官方库演练：作者自己的源码与 Release → 签名 → `plugins/<ID>/plugin.json` → `versions/<版本>.json` → PR → CI → 应用安装与更新。旧版本保留并按新到旧展示。
5. 官方库 CI 不只检查 JSON 字符串格式，还核对真实发布资产的大小、SHA-256 和 Ed25519 签名；明确下载失败或资产下架时的处理方式。
6. 在主仓库和插件仓库提供统一“开发插件”入口，列出 API 支持状态和适用宿主版本。需要新 APK 的宿主接口随新版本发布，不能把 0.03 的能力写成已升级。

最终验收：测试者完成上述两类复杂插件、独立投稿与版本升级；全部操作有可复现记录。未通过的环节继续修复，不以文档篇幅或单次 CI 通过判定完成。

## 主要交付物

| 仓库位置 | 交付物 |
| --- | --- |
| `ABU-launcher/plugin-sdk/` | 脚手架、构建/校验/签名工具、TypeScript 类型、六类参考插件 |
| `ABU-launcher/plugin-sdk/docs/` | 入门、协议、API、复杂插件设计、调试、兼容与迁移文档 |
| `ABU-launcher/Android/app/.../plugins/` | 完整且经过测试的宿主 UI、能力桥、服务和媒体扩展点 |
| `ABU-plugins/CONTRIBUTING.md` | 首次投稿、审核、更新与密钥变更流程 |
| `ABU-plugins/.github/workflows/` | 索引与发布资产的自动校验 |

实施顺序：协议核对 → 宿主能力 → SDK 工具 → 文档与示例 → 独立开发者验收。某项新能力暂时无法完成时，公开文档会标明状态与最低宿主版本，避免开发者以为阅读文档即可调用尚不存在的接口。
