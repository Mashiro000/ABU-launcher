# 从 ABU 0.03 插件迁移到宿主 API 1.1

API 1.1 是**宿主协议版本**，不是插件包版本。已发布的 0.03 APK 不会因为插件清单写入 `hostApi` 就自动具备新 API；必须先安装包含 API 1.1 的新版 APK。新版目前仍在验收，尚未正式发布。

## 老插件继续运行

没有 `hostApi` 的旧清单可以在新版宿主导入、启用和回滚；旧 `render`、`onAction`、存储、网络及事件调用保持可用。新版宿主不会自动修改旧包。旧插件若只使用 0.03 能力，不需要为了兼容而立即升级。

## 使用新功能时怎么改

1. 将插件版本提高，例如 `1.0.0` → `1.1.0`。保持 `id` 和签名公钥不变。
2. 在清单加入 `"hostApi": ">=1.1.0 <2.0.0"`、非空 `author`、有效的 `surfaces`/`slots`/`permissions` 等字段。新版宿主对声明 `hostApi` 的脚本包进行严格检查；`dist/`、`assets/` 外的额外文件会被拒绝。
3. 只声明实际使用的权限与网络域名。`networkDomains` 需要 `network` 权限；`usb.list`/`bluetooth.list` 需要对应插件授权，蓝牙还可能需要 Android 系统权限。
4. 用 `npm run build`、`npm run validate` 重新打包、校验。每次重打包后重新签名，不能复用旧签名。
5. 在新版宿主测试安装、启用、拒绝授权、升级和回滚。宿主最多保留当前版和两个旧版；存储按插件 ID 保留，不因切换版本自动迁移。

## 方法与状态的变化

`render`/`onAction` 仍须**同步**返回 JSON 对象，不能返回 Promise。每次调用重新执行入口脚本；不要依赖全局变量跨调用保存状态。API 1.1 的导航使用 `{navigation:{push:"detail",params:{id:"42"}}}`；下一次 `render` 收到 `route` 和 `params`。返回键由宿主弹栈并恢复焦点。表单临时值在 `onAction.values`，长期数据仍用 `storage.get/set`。

新增的 `data_source`、`subtitle`、服务 RPC 和只读设备 API 只在新版宿主有真正入口。完整播放器页面、后台常驻任务、蓝牙主动扫描、USB 数据传输仍不可用。参见 [API 参考](API_REFERENCE.md) 和 [兼容表](COMPATIBILITY.md)。

## 回滚与失败处理

新版本不兼容时安装器会拒绝安装或启用，不应影响当前版本。作者不能把 `hostApi` 声明降到 0.03 来绕过限制；旧 APK 可能装入但运行时会失败。回滚到旧版前确认旧版能读取现有存储数据；涉及数据结构变更时，应在新版本采用可回退的键或迁移策略，而不是覆盖旧键。若发布签名密钥更换，需要官方库人工审核，不能无提示替换公钥。
